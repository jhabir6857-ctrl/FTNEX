# ASSETS.md — Placing Binary & Real Content Assets

This project scaffold ships with placeholder/stub assets only. The items below are **binary or client-sourced content that cannot be generated by the coding agent** — they must be placed on disk by a human before the relevant components will work as intended. This file tells the agent exactly where things go, what to do while they're missing, and what to update once they arrive.

---

## 1. Hero Frame Sequence (Desktop)

**What:** The exported 3D/AE render sequence for the cinematic scroll hero.

**Where it goes:** `public/frames/desktop/`

**Naming:** `frame_0001.webp`, `frame_0002.webp`, … sequential, zero-padded to 4 digits, matching the order referenced in `lib/scrollFrames.ts`.

**Format:** WebP, 1600px wide (per build spec Section 6).

**If sprite sheets are used instead of individual frames** (recommended per spec Section 6):
- **Where:** `public/sprites/`
- **Naming:** `sprite_01.webp`, `sprite_02.webp`, …

**Agent action once these exist:**
1. Confirm the exact count of frames delivered and the sheet grid layout (columns × rows per sheet, frame width/height in px, frames per sheet).
2. Update the placeholder constants in `lib/scrollFrames.ts` (`TOTAL_FRAMES`, `FRAMES_PER_SHEET`, and the grid math in `getFrameLocation()`) to match the real values — these are currently placeholders and marked `TODO(agent)`.
3. Complete the canvas draw loop in `components/hero/ScrollCanvas.tsx` (marked `TODO(agent)`), using the corrected `scrollFrames.ts` helpers.

**Until these exist:** Do not block other work on this. The site already falls back to `ReducedMotionHero` / the static poster image, so pages and layout can be built and reviewed without the sequence in place.

## 2. Hero Frame Sequence (Mobile) — or Looping Video

**What:** A shorter/lower-res version of the above for mobile, OR a looping background video (`.mp4`/`.webm`), per the still-open decision in build spec Section 10, item 6.

**Where it goes:**
- Frame sequence path: `public/frames/mobile/`, same naming convention as desktop, fewer frames (target ~60–90).
- Video path: place the compressed video file directly in `public/` (e.g. `public/hero-mobile-loop.mp4`) and update `components/hero/ScrollCanvasMobile.tsx` to use a `<video autoPlay muted loop playsInline>` element instead of the current stub.

**Agent action:** Once told which path was chosen, implement `ScrollCanvasMobile.tsx` accordingly (currently a stub with both options documented in its comments).

## 3. Poster / LCP Placeholder Image

**What:** A single low-res, blurred still frame used as the hero's poster image — this is the intended Largest Contentful Paint element (build spec Section 6) and is also the fallback hero image shown by `ReducedMotionHero`, and used as a temporary placeholder image across About/Services/Fleet/Partners/Contact hero banners and fleet cards in the current scaffold.

**Where it goes:** `public/frames/poster.webp` — **this exact filename**, since it's referenced directly by path in multiple components (`ScrollCanvas.tsx`, `ScrollCanvasMobile.tsx`, `ReducedMotionHero.tsx`, and the static page hero banners).

**Agent action once real vessel/brand photography exists:** Once dedicated hero images exist for About/Services/Fleet/Partners/Contact banners (rather than reusing the single poster image as a stand-in), replace those `<Image src="/frames/poster.webp" .../>` calls in each `app/*/page.tsx` file with the correct dedicated image path.

## 4. Partner Logos, Vessel Photography, Vector Icons

**What:** Real partner/client logos, real vessel photographs for the Fleet page, and the reused 2D vector explainer assets (service icons, etc.) referenced in the build spec's asset pipeline (Section 2).

**Where they go:**
- Partner logos → `public/vectors/` (referenced by `data/partners.ts` → `logo` field)
- Vessel photography → anywhere under `public/` (referenced by `data/fleet.ts` → `image` field) — e.g. `public/fleet/vessel-001.webp`
- Service icons / vector explainer assets → `public/vectors/` (referenced by `data/services.ts` → `icon` field)

**Agent action once these exist:** Update the corresponding `logo`, `image`, and `icon` fields in `data/partners.ts`, `data/fleet.ts`, and `data/services.ts` to point at the real file paths, replacing the current placeholder paths.

## 5. Final Copy & Real Content (Non-Binary, But Still Blocked on Client Input)

**What:** All text currently marked `[PLACEHOLDER]` throughout `data/services.ts`, `data/fleet.ts`, `data/partners.ts`, `data/site-config.ts`, and inline in the page files (`app/**/page.tsx`) — headline/subhead copy, service descriptions, real stats (years in operation, fleet size, etc.), real office locations and contact emails, and real social links.

**Agent action once client content is provided:** Search the codebase for the literal string `[PLACEHOLDER]` and replace each instance with the confirmed real content. Do not remove the `[PLACEHOLDER]` marker convention for anything still unconfirmed — it exists specifically so remaining placeholder content stays easy to find via search, rather than being mistaken for final copy.

**Do not invent:**
- Office addresses/phone numbers/emails (`data/site-config.ts`) — FTNEXT's real offices are not confirmed to match the Akij Shipping reference; do not carry those over.
- Real statistics (years of operation, fleet count, tonnage, countries served) — these are currently invented placeholder numbers for layout purposes only.
- Final service names/descriptions — currently mirror Akij's category set as a structural placeholder per build spec Section 5.1, not confirmed as FTNEXT's actual service lineup.

## Summary Checklist

| Asset | Destination | Blocks |
|---|---|---|
| Desktop frame sequence or sprite sheets | `public/frames/desktop/` or `public/sprites/` | Full `ScrollCanvas` hero |
| Mobile sequence or video | `public/frames/mobile/` or `public/*.mp4` | Mobile hero |
| Poster image | `public/frames/poster.webp` | LCP, fallback hero, all page banners |
| Partner logos | `public/vectors/` | Partner page/section |
| Vessel photography | `public/` (any subfolder) | Fleet page |
| Service/vector icons | `public/vectors/` | Service cards |
| Real copy, stats, offices | Inline + `data/*.ts` | All pages (currently placeholder) |

Nothing in this list blocks the initial build — the scaffold is designed to run and look structurally complete with placeholders in place. These items block the site being launch-ready, not development-ready.
